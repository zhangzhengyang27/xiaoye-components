# 仓库架构地图

> 本文档是《xiaoye-components 组件库源码专栏》的阶段一交付物之一，基于全仓扫描产出（2026-09-16 修订：字重令牌扩档、生成物守卫等实态对齐），作为后续全部篇章的事实基线。所有文件路径均相对仓库根目录。

## 一、仓库定位与发布现状

xiaoye-components 是一套 **AI 协作研发** 的 Vue 3 企业级组件库 monorepo，以 Stripe 设计语言为视觉蓝本。当前发布状态（本地与 npm 同步）：

| 包 | npm 名 | 版本 | 角色 | 发布状态 |
|---|---|---|---|---|
| packages/components | `xiaoye-components` | 1.1.0 | 基础组件层（72 个组件） | 已发布 |
| packages/pro-components | `xiaoye-pro-components` | 2.0.0 | 增强组件层（31 个组件） | 已发布（独立大版本） |
| packages/xiaoye-primitives | `xiaoye-primitives` | 1.1.0 | 基础设施层（composables + utils + 令牌源） | 已发布 |
| packages/mcp-server | `xiaoye-mcp-server` | 0.1.1 | AI 工具 MCP Server | 已发布 |
| packages/theme | `@xiaoye/theme`（private） | — | 全部组件样式（约 1.84 万行 CSS） | 内部 |
| packages/tokens | `@xiaoye/tokens`（private） | — | 令牌 TS 常量层（生成物） | 内部 |
| apps/docs | `@xiaoye/docs`（private） | — | VitePress 文档站 | 内部 |
| apps/playground | `@xiaoye/playground`（private） | — | 本地联调 | 内部 |

四个发布包独立版本（changesets `fixed: []`），跨包联动靠 `updateInternalDependencies: "patch"`。

关键依赖设计：

- **严格单向**：`pro-components → components → primitives → (@floating-ui/dom, vue peer)`，无环。
- **内部依赖 peer 化**：pro-components 对 components 用 `peerDependencies: workspace:^`（`packages/pro-components/package.json`），保证宿主应用与增强层共享同一基础库实例——`Symbol.for` 安装标记与 ConfigProvider 的 provide/inject 才能跨包生效。
- **消费侧零依赖声明**：docs 与 playground 不声明任何依赖，全靠 `scripts/config/aliases.ts` 的统一 alias 直连源码（该文件被库构建 / vitest / 文档站 / playground 四条工具链复用）。
- **primitives 是逻辑包也是主题包**：`packages/xiaoye-primitives/src/theme/tokens.css` 是全库设计令牌唯一事实源，同时承载浮层 composables；`components/src/composables/index.ts` 一行 `export * from "xiaoye-primitives"` 做二次转发。

## 三、六大核心机制（横向主线）

### 1. 清单驱动（manifest-as-constitution）

`packages/components/component-manifest.json`（72 条）与 `packages/pro-components/component-manifest.json`（31 条）是各自层的唯一数据事实源，同时驱动：

1. `exports.ts` 导出聚合
2. `index.ts` 全局安装列表（`installableComponentExportNames` 鸭子类型过滤）
3. 文档站侧边栏（`config.ts` 直接 import manifest.ts）
4. 样式聚合（`styleImports` ↔ `theme/index.css` 的 `@import` 双向 diff）
5. 一致性校验（`scripts/check-components.mjs` 六向校验、`scripts/check-pro-components.mjs` 十一组校验，均挂进 `pnpm lint`）
6. MCP Server 数据骨架（`scripts/generate-llm-files.mjs`）

### 2. 浮层体系（primitives 浮层七件套）

全库浮层（tooltip/popover/popconfirm/dropdown/dialog/drawer + 7 个表单弹层 + image-viewer + menu 子菜单）共享同一组基础设施：

| composable | 职责 |
|---|---|
| `use-floating-visibility.ts` | visible/rendered/isAnimating 三态状态机、开闭延迟、动画期 toggle 守卫 |
| `use-overlay-stack.ts` | 模块级全局浮层栈，zIndex 自 2000 发号，`isTopMost` 栈顶裁决 |
| `use-floating-panel.ts` | @floating-ui/dom 定位封装（offset/flip/shift/size/arrow 管道） |
| `use-dismissible-layer.ts` | Escape/外点关闭统一收口，栈顶守卫 |
| `use-overlay-dialog.ts` | 模态编排层（teleport/destroyOnClose/modal/lockScroll 聚合） |
| `use-focus-trap.ts` | 焦点陷阱（Tab 循环/焦点还原/逃逸拦截） |
| `use-list-navigation.ts` | 列表键盘导航（上下/Home/End/循环） |

### 3. 令牌三层架构与双主题

`packages/xiaoye-primitives/src/theme/tokens.css`（410 行）：基元层 58 个（`--xy-{色板}-{阶}`，双主题共享）+ 语义层 66 个（`--xy-{角色}[-{状态}]`，暗色只覆写 58 个值）+ 刻度层 45 个（`--xy-{刻度}-{档}`，主题无关；字重 12 档）。切换协议为 `[data-theme="dark"]` 属性，组件 CSS 中 `[data-theme]` 选择器出现 **0 次**（纯变量级联换肤）。`--xy-mix-light` 变量在暗色下从白色反转为容器底色，使全库 800+ 处 `color-mix()` 公式同一写法下语义自动反转。生成物 TS 常量层由 `pnpm generate:tokens` 产出（`packages/tokens/src/*`），同步性由 `check:tokens` 守卫。

### 4. 命令式服务与 Context 捕获

message/notification 两类走 `withInstallFunction` 在 `app.use` 时捕获 `app._context`；loading 指令+服务双注册（manifest 双 kind）；dialog 服务采用 `reactive({ current, queue })` 串行队列 + 每 entry 自带 Promise resolver 的句柄模型（alert 服务为同族变奏）。树外配置经 config-provider 的四组全局注册表下发。

### 5. AI 生态四层体系

`llms.txt`（发现，手写）→ `llms-full.txt`（参考，约 19.3 万字符，脚本从文档 md 反向解析生成）→ `scripts/.llm-cache/api-schema.json`（数据，103 组件）→ `xiaoye-mcp-server`（查询层，list_components / get_component_api / search_components 三工具 + 内置选型指导 prompt）。生成物同步由 `check:llms` 守卫。

### 6. 三层质量防线 + e2e

- **单测**：vitest + jsdom，114 个 spec，`vitest.setup.ts` 全局 mock `@iconify/vue`；
- **类型夹具**：`tests/types/fixtures/` 105 个夹具，`@ts-expect-error` 负向断言锁死类型契约（含 `pro-root-boundary.ts` 守卫增强层 API 面）；
- **视觉巡检**：`scripts/visual-audit.mjs`，Playwright 元素级截图 × 双主题 × pixelmatch 0.5% 阈值 + 基线目录（1064 张）；
- **e2e**：Playwright 以文档站为宿主（`vitepress dev` 起 webServer），`tests/e2e/admin-flow.spec.ts` 走真实业务闭环、`docs-demos.spec.ts` 高危 demo 定点回归。

## 四、工程化链路速览

- **构建**：三库包共享根级工厂 `scripts/config/library-build.ts` 的 `createLibraryConfig`，ES-only 单格式，dts 输出 `dist/types`；`scripts/prepare-package.mjs`（808 行）做发布级 d.ts 后处理（别名重写、SFCWithInstall 泛型简化、TS Compiler API 重建组件 index.d.ts）。
- **发布**：`pnpm changeset` → push main → release.yml 开 Version Packages PR → 合并后自动 build:lib + changeset publish；release job 内重跑 check/typecheck/test/build 做**门禁兜底**（防直推 main 绕过 CI）。
- **CI**：ci.yml 依次跑 check → lint → typecheck → test（`--no-file-parallelism` 防 OOM，注释记录踩坑）→ build；lint 链前置四道守卫（check:tokens / check:llms / check:components / check:pro-components）；docs.yml 仅构建冒烟。
- **文档站 demo 三件套**：markdown-it 容器插件（`:::demo` 语法）+ Vite pre-transform 插件（自动注入异步组件与虚拟模块导入）+ `virtual:xy-demo-source:*` 内存注册表——「运行的代码 = 展示的代码」，另附 TS→JS 双视图（`utils/ts2js.ts`）。
